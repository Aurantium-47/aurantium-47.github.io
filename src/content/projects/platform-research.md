## 解决什么问题

资料分散在中文内容平台与技术社区里。搜索能找到一个标题，不一定意味着正文、评论或字幕都能读到。

我把不同渠道的优先顺序、实测范围和失败处理整理成了可复用的 Skill。之后开展调研时，AI 能按照已有经验选择渠道，并说明实际读到了什么。

## 已经验证的范围

| 平台或渠道 | 实测内容 | 仍有边界 |
| --- | --- | --- |
| 哔哩哔哩 | 登录、搜索；另一路浏览器读取内容 | MCP 字幕与评论曾返回 412，不能声称全部可读 |
| 微信公众号 | 搜索、文章读取、保存 Markdown / HTML 与图片 | 读取与自动发布属于不同流程 |
| 小红书 | 登录浏览器搜索、原帖文字与图片 | 没有完整覆盖全部评论 |
| 知乎 | 登录后搜索与专栏正文 | 每篇内容仍需要核验 |
| 抖音 | 登录后搜索、图文原帖与元信息 | 完整视频转写未验证 |
| 技术社区接口 | 协议与搜索工具接入；部分站点支持评论文本 | 协议通过不代表每个平台内容均已深读 |

这些结果来自本机阶段性实测，平台变化后需要重新核验。

## 这套方法的价值

MCP 提供结构化工具入口，浏览器处理需要登录的原帖阅读，CDP 支持浏览器连接；Python 用于整理内容和工具调用。遇到失败时保留原因，换可用渠道继续，并把来源链接带进最终结论。

真正积累下来的是“哪条路线读到了什么、哪一步会失败”的经验。它让下一次调研少重复试错。
