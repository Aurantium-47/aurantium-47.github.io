# 橙子的个人网站使用说明

网站：<https://aurantium-47.github.io/>  
共享仓库：<https://github.com/Aurantium-47/aurantium-47.github.io>

## 最推荐的方式

**用 GitHub 同时保存网站内容和简短项目进度，让 dot 和各个本地对话直接读写同一个仓库。**

网站是给人看的个人空间，仓库是给 AI 接着工作的资料库。每次只留下成果、证据和下一步；不再反复复制整个对话。更新 Markdown 后，GitHub Actions 自动生成并发布网页。

Slack 可做通知渠道，但不会自动变成共享记忆。现在只维护 GitHub 更省事。如果以后确实需要消息提醒，再加 Slack 即可。

这不是完整聊天记录同步。一个 AI 看不到另一个对话中的所有上下文，需要的结论应当写进案例文件和进度文件。

## 一次性接入 dot

给 dot 一次下面这段话。仓库链接之后保持不变。

> 我们共同维护我的个人网站：https://github.com/Aurantium-47/aurantium-47.github.io 。请先读 README、AGENTS.md、docs/使用说明.md 和 collaboration/status.md。今后你为我完成且我要求公开的成果，整理成 src/content/projects 下的案例，写清用途、我的角色、实际技术栈、真实演示和验证边界；结束时更新简短进度并提交到仓库。开始下一项工作前先看共享进度。请在你的云电脑上完成能独立完成的调研、整理与修改；只在确实需要本机文件或软件时使用我的电脑。先检查你是否能读取并提交此仓库，缺少权限时告诉我具体的连接步骤。

如果希望它主动跟进，再加：

> 请持续跟进这个仓库的新增成果，发现有价值的新案例或缺少证据时帮我整理。状态未变化时保持安静；有完成项、问题或需要我提供素材时告诉我。请使用你支持的跟进或计划功能落实，并告诉我实际配置结果。

此说明书不会自己给 dot 配置连接或计划任务。必须由 dot 在其产品内确认仓库访问及跟进配置，才算接入完成。

## 一次性接入本地对话

给「调研 Codex 额度创意用法」以及其他需要参与的对话这段话：

> 我的个人网站统一维护在 https://github.com/Aurantium-47/aurantium-47.github.io 。请读仓库的 AGENTS.md 和共享进度。以后在这个对话里完成且我要求公开的成果，直接按模板整理进该仓库，结束时写回进度。复用已有案例；无需让我导出整个聊天。修改前同步远端，完成后运行 npm run build 并提交。

新对话只需要知道仓库地址。它能读到已经整理的内容，并按同一套规则接续。

## 以后增加一项成果

直接告诉当前对话：

> 把本次成果加入我的个人网站。先读仓库规则，使用真实材料，补上用途、实际技术栈、截图或演示、本人角色和实现边界；更新共享进度，检查通过后发布。仓库是 https://github.com/Aurantium-47/aurantium-47.github.io 。

如果成果在另一个旧对话里：

> 去深读「对话名称」里的这项成果，把可公开的结果整理进网站；找不到关键证据就保留待补状态。

本地 Codex 能在有权限时读取其他本地对话；dot 能访问哪些历史或本地材料取决于其连接和产品支持。仓库已经整理的内容不需要再从对话读取。

也可以自己创建一个文件：从 `templates/project.md` 复制到 `src/content/projects/项目英文名.md`。文件名就是页面地址的一部分，之后尽量不改。填写开头的字段，再写正文。将 `draft` 设为 `false` 后，构建时会加入网站。

| 状态 | 什么情况下使用 |
| --- | --- |
| 已完成 | 有可运行成品或明确交付，且有验证记录 |
| 部分实测 | 部分路径跑通，仍有未验证能力 |
| 调研记录 | 研究与比较，尚未声称完成实现 |
| 待补证据 | 用户做过但当前未核实，等待原材料 |

## 写随记或日记

从 `templates/note.md` 复制到 `src/content/notes/英文文件名.md`。`kind` 可以是“随记”“日记”“分享”。正文用普通 Markdown；按真实想法编辑后，将 `draft` 改成 `false` 即可。

AI 可以帮你整理已经说过或写过的内容，但不替你编造一天发生的事。私人日记放在私有位置，不要提交到这个公开仓库。

## 添加照片

把明确要公开的照片放到 `public/photos/`，在 `src/data/photos.json` 的数组里添加：

```json
{
  "src": "/photos/my-photo.jpg",
  "alt": "照片内容的具体描述",
  "caption": "我想留下的说明",
  "date": "2026-10-01",
  "public": true
}
```

多张照片用逗号分隔。照片页点击可打开原图。建议先导出适合网页的尺寸，再加入仓库；涉及他人的照片先确定适合公开。数学海报放在 AI 成果中，不替代本人的生活照片。

## 补正式简历

编辑 `src/data/resume.json`。`education` 和 `experience` 都是数组，每项包含 `title`、`period`、`description`。已公开的实践自动来自同一批项目内容，不用维护两份项目介绍。

```json
{
  "title": "真实学校、专业或职位",
  "period": "真实起止时间",
  "description": "真实经历与工作内容"
}
```

项目简历页有“打印 / 保存为 PDF”按钮。现版没有教育与工作经历，因为尚未提供正式材料。未来可以增加已确认的内容，但不要为了看起来丰富而补虚构经历。

## 手动修改与自动发布

1. 打开仓库，找到文件，点编辑铅笔，保存提交；或者让 AI 修改并提交。
2. 查看仓库 Actions：构建通过后，网页自动更新。PR 只做检查，不部署；`main` 才发布。
3. 访问网站核对修改。如果旧内容仍在，等部署结束后再刷新。

本地操作：

```sh
git pull --ff-only
npm ci
npm run dev
npm run build
git add 要提交的文件
git commit -m "描述本次修改"
git push
```

遇到同一文件冲突先看两边修改，再合并；不强制推送覆盖其他对话的工作。

## 为什么不用一直开着本地电脑

静态网站由 GitHub Pages 托管，访问网站不依赖本地电脑。dot 在自己的云电脑上读写仓库也不依赖本机在线。只有需要本地文件、软件或本地任务时，才需要本机连接。

连接本机是一项访问权限，不能单靠它判断使用哪份额度。官方文档区分：dot 自身工作不计入 ChatGPT 对话用量；由 dot 发起或管理的 Codex / Work 任务按对应产品的用量计算。dot 的深度工作有自己的计划额度，首月延长限额也不等于所有工作免费。希望多用 dot 额度，就让 dot 直接在其云电脑上执行适合它的任务，而不要把每项工作都转成 Codex 任务。

云电脑提供独立运行环境和不依赖本机在线的执行能力，不会增加本地电脑的可用内存。官方没有在本次查到的说明里承诺具体 RAM 大小。

官方说明：[dot](https://learn.chatgpt.com/docs/dots)、[电脑与应用](https://learn.chatgpt.com/docs/dots/computers-and-apps)、[任务与记忆](https://learn.chatgpt.com/docs/dots/tasks-and-memory)。额度与产品能力会变化，以当时账户和官方说明为准。
